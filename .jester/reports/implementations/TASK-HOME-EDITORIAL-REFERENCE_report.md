## რეალური ინტეგრაციები და დაცვა

- უცვლელია `profiles/me`, `interpretations/daily-energy`, `interpretations/discovery-people`, `connections` და accepted კავშირის `people/{id}/why` კონტრაქტები.
- `HomeAvatar` / `ProfileImage` კვლავ იყენებს ავტორიზებულ ფოტოს მიღებას. Chrome-ში დადასტურდა accepted ადამიანის ფოტოს `blob:` მისამართი; ტოკენი DOM-ში არ თავსდება.
- შენარჩუნებულია არსებული query keys, error/retry, loading/empty მდგომარეობები, დაკვირვების provenance, copy feedback, DO/DON'T, ფილტრები და გვერდებად დაყოფა.
- კავშირების სახელები/ფოტოები მოდის backend-ის `other_display_name` / `other_avatar_url` ველებიდან; არ არსებობს გამოგონილი online სტატუსები ან მომხმარებელთა რაოდენობა.
- საუბრის ზოგადი კითხვა არ არის წარმოდგენილი პერსონალიზებულ გამოთვლად. accepted კავშირის მქონე მომხმარებელი გადადის Messages-ში; სხვა შემთხვევაში Discover-ში. მოწვევა თავისით არ ქმნის საუბარს და არ აგზავნის შეტყობინებას.
- უცვლელია shared `HomeNavigation`, `HomeMobileNavigation`, `HomeElements`, ავტორიზაცია და შეტყობინებების არსებული ინფრასტრუქტურა.
- backend, ბაზის სქემა, მიგრაციები, RLS და ასტროლოგიური გამოთვლები არ შეცვლილა. დესტრუქციული regression fixtures არ გაშვებულა.

რეალურ Chrome-ში ორი დროებითი, მონიშნული QA ანგარიშით დადასტურდა:

1. კავშირის არმქონე ანგარიშის CTA მიდის Discover-ში.
2. API request → მეორე ანგარიშის accept → Home reload აჩვენებს რეალურ კავშირს და დაცულ ფოტოს; მოწვევა Messages-ზე გადადის.
3. 1440, 1280, 768, 390 და 360px-ზე ჰორიზონტალური გადაცდენა არ არის. მთავარი CTA, სწრაფი მოქმედებები და მობილური ნავიგაცია მინიმუმ 44px სიმაღლისაა.
4. Hero → Discover, Connections, Messages და ნამდვილი Person Profile ბმულები მუშაობს.
5. daily-energy მოთხოვნის ხელოვნური ქსელური შეწყვეტა აჩვენებს შესაბამის შეცდომას, კავშირები რჩება, Retry აღადგენს რეალურ პასუხს.
6. დაუმუშავებელი browser exception არ დაფიქსირებულა.

პირველ რენდერში 390px-ზე დეკორატიულ ორბიტას ჰქონდა მცირე overflow; გასწორდა დეკორის საზღვრებით. ეკრანების დათვალიერების შემდეგ გასწორდა ნარინჯისფერ CTA-ზე ტექსტის კონტრასტი და მობილური quick-action ფონის სიგანე. არსებული 360px ნავიგაცია 44px-ია; ეს სიდიდე არ შემცირებულა და არც 48px-ად არის გამოცხადებული.

QA-ის ბოლოს წაიშალა მხოლოდ manifest-ით დადასტურებული დროებითი ანგარიშები და მათი მედია. არსებული მომხმარებლების მონაცემები არ გადატვირთულა.

## განსხვავებები და შეზღუდვები

- გამოყენებულია რეპოზიტორიის არსებული ორი editorial ფოტო; პოსტერის მომღიმარი ქალისა და კაცის ცალკეული ორიგინალი ფოტოები არ არის მოწოდებული. ფოტოების ახალი ლიცენზია ამ სამუშაოთი არ დასტურდება.
- შენარჩუნებულია მოქმედი JESTER ლოგო და ქართული შრიფტი; პოსტერის განსხვავებული wordmark არ ჩაგვინაცვლებია.
- რეალური პროფილების ნაწილს ფოტო არ აქვს; ჩანს ინიციალები. რეალური ცარიელი ადგილები გამოგონილი ადამიანებით არ შევსებულა.
- რეალურ ინსაითს მეტი ტექსტი და განმარტება აქვს, ვიდრე პოსტერზე. disclosure-ები, error/retry და privacy provenance შენარჩუნებულია, ამიტომ გვერდის სრული სიმაღლე განსხვავდება.
- მონაცემთა სიმცირისას კავშირების სია ბუნებრივად მოკლეა; არ არის ხელოვნურად დამატებული სამი მონაწილე.
- Vite კვლავ აფრთხილებს 500kB-ზე დიდ საერთო JS chunk-ზე. კოდის დაყოფა და არსებული დიდი ფოტოაქტივების ოპტიმიზაცია ამ Home ამოცანის ფარგლებს არ გაფართოებია.
- დამატებითი unread/realtime backend ცვლილებები არ განხორციელებულა; Home-ის ვიზუალური ამოცანა Wave 5-ს არ იწყებს.
- 18+ ტექნიკური enforcement და moderation-ის საჯარო გაშვების საკითხები ამ UI სამუშაოთი არ იხურება.
